# Backend demo run sheet (Express + Node)

Two processes, two DevTools windows: one for the page, one for Node.

| Process | Port | Started by |
| --- | --- | --- |
| Vite (frontend) | 5173 | `npm run dev` |
| Express API | 8787 | `npm run dev:api` or `npm run dev:debug` |

The browser calls `/api/...` on its own origin; Vite proxies it to Express
(`vite.config.ts:7-14`). That is why there is no CORS configuration.

## 1. Start

```bash
cd "/Users/atulya/College Stuff/OneDayOneYear-main"
lsof -ti:5173 -ti:8787 | xargs kill     # clear stale ports
npm run dev                             # terminal 1
npm run dev:debug                       # terminal 2: node --inspect server/index.mjs
```

`dev:debug` prints `Debugger listening on ws://127.0.0.1:9229/...`.
Do not run `dev:full` at the same time: it binds 8787 and the debugger port stays closed.

Rate limit is 10 submissions / 10 min per process. During rehearsal either restart
the API (the window resets) or raise it:

```bash
SUBMISSION_RATE_LIMIT=100 npm run dev:debug
```

## 2. Frontend side (page DevTools)

1. Open http://localhost:5173/contribute
2. DevTools -> Network -> filter Fetch/XHR -> tick Preserve log
3. Submit the form; click the `submissions` request
   - Headers: `POST`, `Content-Type: multipart/form-data; boundary=...`
   - Payload: `name`, `date`, `description`, `evidence`
   - Response: `201` + `{ id, receivedAt, status, name, date }`
4. Sources -> `src/api/submissions.ts` -> breakpoint `41` and `50`
5. Submit again, then in the console:

```js
values                    // form state passed to the API layer
[...body.entries()]       // the four multipart parts
response.status           // 201 (after stepping over the fetch)
payload                   // the receipt returned to the UI
```

## 3. Backend side (Node DevTools)

1. Chrome -> `chrome://inspect` -> Remote Target -> `inspect` on `server/index.mjs`
   (add `localhost:9229` under Configure if the target is missing)
2. Sources -> Filesystem -> add the project folder, open `server/index.mjs`
3. Set breakpoints, then submit from the page again

| Breakpoint | Inspect | Proves |
| --- | --- | --- |
| `index.mjs:98` | `req.method`, `req.body`, `req.file.mimetype` | server re-validates client input |
| `index.mjs:100` | `errors` | rejected fields and their messages |
| `store.mjs:60` (F11 from `104`) | `existing.length`, `DATA_FILE` | read happens inside the write queue |
| `store.mjs:66-69` | temp path, then `UPLOAD_DIR` | write then atomic rename |
| `index.mjs:112` | `file.buffer.length` | evidence written to uploads |

Raw request inspection at `index.mjs:98`:

```js

```

## 5. Error branches

```bash
# validation: 400 with field errors
curl -s -X POST http://127.0.0.1:8787/api/submissions \
  -F "name=A" -F "date=2999-01-01" -F "description=short" -w '\n%{http_code}\n'

# wrong MIME: 400 with errors.evidence
curl -s -X POST http://127.0.0.1:8787/api/submissions \
  -F "name=Test" -F "date=1969-07-20" -F "description=012345678901234567890" \
  -F "evidence=@package.json;type=application/pdf" -w '\n%{http_code}\n'

# oversize: 413 (create the file first: mkfile -n 21m /tmp/big.jpg)
curl -s -X POST http://127.0.0.1:8787/api/submissions \
  -F "name=Test" -F "date=1969-07-20" -F "description=012345678901234567890" \
  -F "evidence=@/tmp/big.jpg" -w '\n%{http_code}\n'
```

In the UI, submit a one-character name and break on `index.mjs:100`: the same
`errors` object the page renders as inline messages.

## 6. Talking points

- Node ESM: no build step, `import`, top-level `await ensureStore()` (`index.mjs:35`).
- Express 5: `app.use('/api', ...)` as the JSON 404 catch-all (`:147`), `app.listen`
  without a callback plus a `server.on('error')` handler (`:151-174`).
- Writes are serialised by a promise queue and land via temp file + `rename`, so a
  crash cannot truncate the JSON (`store.mjs:59-79`).
- Accession is max-sequence + 1 inside the queue, so concurrent submissions cannot
  collide (`store.mjs:38-51`).
- Rate limiting is in-memory per process, not a security boundary (`index.mjs:47-63`).

## 7. Known limits (say these before they are found)

- No auth on `POST` or `GET /api/submissions`.
- Evidence MIME is client-declared; no magic-byte sniffing.
- Whole-file rewrite per append; fine for tens of records.
- Uploads are written but not served (no `express.static`).
- No automated tests; verification is manual plus curl.

## 8. Browser-only run (10 minutes)

Terminal work is step 0 only; everything else is Chrome.

0. `lsof -ti:8787 | xargs kill`, then `npm run dev` and `npm run dev:debug`
1. Window A: http://localhost:5173/contribute
2. Cmd+Opt+I -> Network -> Fetch/XHR -> Preserve log -> Disable cache
3. Submit a valid record -> click `submissions`
   - Headers: `POST` + multipart boundary
   - Payload: name, date, description, evidence
   - Response: `201` + `id`
4. Sources -> Cmd+P -> `submissions.ts` -> breakpoints `41`, `50`, `66`
5. Submit again -> at `41` console `values` and `[...body.entries()]`;
   F10 twice -> `response.status` is `201`; F10 -> `payload`;
   F11 -> `useContributionForm.ts:68` -> step to `69`/`70`
6. Window B: `chrome://inspect` -> Remote Target -> `inspect` on `server/index.mjs`
7. Window B: Sources -> Filesystem -> Add folder -> project root -> open `server/index.mjs`
8. Breakpoints: `index.mjs` `98`, `100`, `104`, `133`; `store.mjs` `60`, `66`, `69`
9. Submit again from Window A
   - `98`: `req.method`, `req.body`, `req.file?.mimetype`, `req.headers['content-type']`
   - F11 into `validateSubmission`, step, return with `errors` and `values`
   - `104`: F11 into `store.mjs:61` -> `existing.length`; `66` temp path; `69` rename
   - `112` evidence buffer size; `122` record object
   - `133`: F10 -> `201` sent
10. No terminal needed for proof, in Window A's console:
    `await (await fetch('/api/submissions')).json()` and
    `await (await fetch('/api/health')).json()`
11. Error branch: submit with a one-character name -> pause at `100` -> `errors` -> `400`
12. Cleanup: Cmd+F8 or Breakpoints -> Remove all; close Window B; stop both terminals
