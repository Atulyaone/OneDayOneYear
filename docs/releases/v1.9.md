# v1.9 — Submission portal and JSON persistence API

**Released:** 28 October 2026
**Commit:** [`b74a368`](https://github.com/Atulyaone/OneDayOneYear/commit/b74a368d374f39a30394cc40e492752f284873f0)
**Compare:** [`d0877ae...b74a368`](https://github.com/Atulyaone/OneDayOneYear/compare/d0877ae...b74a368)

Evaluation 2 asked for four capabilities: additional pages linked together, real JavaScript interactions, working form submission, and submitted data saved to local JSON files. This release delivers all four on top of the cinematic archive from v1.8, without changing the archive's visual language.

---

## The four requirements

| Requirement | Where it is delivered |
|---|---|
| Additional pages, linked together | `/contribute`, `/admin/submissions`, plus cross-links from `/about` and every record footer |
| JavaScript interactions | Validated form, inline field errors, error summary, live character counter, evidence picker with preview, submitting/error/success states, receipt |
| Form submission | `POST /api/submissions` (multipart) through the Express API, proxied by Vite |
| Local JSON persistence | Every accepted record appended to `server/data/submissions.json`; evidence written to `server/uploads/` |

## 1. Submission portal — `/contribute`

A new archival submission page, built from the same typography, rules, and dark palette as the rest of the archive.

- **Fields:** researcher name, historical date, record description, optional photographic or video evidence.
- **Validation on submit and on blur:** the first invalid field receives focus, and a summary announces the error count.
- **Character counter** on the description (20–4,000 characters) with a hard `maxLength` cap.
- **Evidence picker** accepts JPEG, PNG, WebP, MP4, and WebM up to 20 MB, previews images locally, and can be cleared.
- **States:** idle, submitting, server error, and success.
- **Receipt:** the accepted record is shown back with its accession number, contributor, date, received time, and `pending` status.
- **Prefill:** `/contribute?date=1969-07-20` opens with the date already set, which is how record pages and the calendar link into the form.
- **`/submit` is now a permanent redirect to `/contribute`**, so older links keep working.

## 2. Express API

`server/index.mjs` — Node, Express 5, Multer. Started alongside Vite by `npm run dev:full`.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/health` | Liveness plus record count |
| `GET` | `/api/submissions` | All stored records |
| `POST` | `/api/submissions` | Create a record (multipart) |

```http
POST /api/submissions
Content-Type: multipart/form-data

name         string   required, 2–120 characters
date         string   required, YYYY-MM-DD, valid, not in the future
description  string   required, 20–4000 characters
evidence     file     optional, JPEG/PNG/WebP/MP4/WebM, 20 MB max
```

```json
201 Created
{
  "id": "SUB-20261028-0003",
  "receivedAt": "2026-10-28T20:49:00.000Z",
  "status": "pending",
  "name": "Harshita Rao",
  "date": "1969-07-20"
}
```

Failure responses carry field-level messages so the form can show them inline:

```json
400 Bad Request
{
  "message": "Some fields need attention.",
  "errors": { "date": "The date cannot be in the future." }
}
```

| Status | When |
|---|---|
| `201` | Record stored |
| `400` | Validation failed or upload unreadable |
| `413` | Evidence larger than 20 MB |
| `429` | More than 10 attempts from one address in 10 minutes (`Retry-After` set) |
| `500` | Store could not be written |

Every rule is enforced twice: once in the browser (`src/data/validation.ts`) and again in the API (`server/validation.mjs`), because browser validation can be bypassed.

## 3. Records saved as local JSON

```text
server/
├── data/submissions.json     appended record store (committed, starts as [])
└── uploads/                  evidence files (git-ignored)
```

Each accepted submission is appended as one object:

```json
{
  "id": "SUB-20261028-0003",
  "receivedAt": "2026-10-28T20:49:00.000Z",
  "status": "pending",
  "name": "Harshita Rao",
  "date": "1969-07-20",
  "description": "…",
  "evidence": {
    "originalName": "moon-landing.jpg",
    "storedName": "SUB-20261028-0003-evidence.jpg",
    "mimeType": "image/jpeg",
    "size": 184320,
    "path": "uploads/SUB-20261028-0003-evidence.jpg"
  }
}
```

`evidence` is `null` when nothing was attached.

**Write safety.** Appends are serialised through a promise queue and land via a temporary file plus `rename()`, so a crash mid-write cannot leave truncated JSON behind. Accession numbers are allocated inside that queue as `SUB-YYYYMMDD-NNNN`, sequential per day, so concurrent submissions cannot collide.

## 4. Review register — `/admin/submissions`

Read-only archive office view of everything the API has stored, matching the same editorial layout. It has an empty state for a fresh store. It is intentionally unauthenticated for this evaluation build.

## Accessibility and performance

- Custom cursor is scoped to fine pointers only; touch and keyboard users keep the system cursor.
- Text selection is no longer blocked.
- Reduced motion renders the final newspaper frame as a static image instead of scrubbing 242 frames.
- Frame sequence loads in batches of 8, with a stride on narrow viewports (82 requests on mobile instead of 242).
- Validation errors and the receipt are announced through `aria-live` regions; focus moves to the first invalid field on a failed submit.

## Upgrading from v1.8

- **Rebase before pulling.** `main` now also contains `d0877ae` from a teammate; v1.9 sits on top of it.
- **Replaced submission path.** The old `SubmissionPage.tsx` and the dev-server-only JSON middleware added in `d0877ae` were removed. `/submit` redirects to `/contribute`, and `/api/save-submission` no longer exists — use `/api/submissions`.
- **New dependencies:** `express`, `multer`, `concurrently`, `vite-plugin-svgr`. Run `npm install`.
- **Start with both processes.** `npm run dev:full`, not `npm run dev`.
- **Fresh store.** `server/data/submissions.json` ships as `[]`; evidence uploads are git-ignored. To reset the register, write `[]` back to the file and clear `server/uploads/` (keeping `.gitkeep`).
- **Ports** default to `5173` and `8787`; the API honours `PORT` and `SUBMISSION_RATE_LIMIT`.

## Known issues

- Search still uses the v1.5 prefix/date/month matcher, so keyword queries such as `moon` or `nasa` return nothing.
- `src/frames/` duplicates the 19 MB `public/frames/` set.
- Records stay `pending` until a moderation workflow exists, and the admin register has no authentication.
- No automated test suite yet; verification was manual plus scripted API checks.
- Production bundle still triggers Vite's chunk-size warning.
